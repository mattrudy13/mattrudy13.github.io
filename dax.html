Power BI measures I reach for, each with made-up numbers and what the visual shows. Every example uses one base measure, Sales = SUM ( Sales[Amount] ), and a date table marked as the model's date table.

Year to date vs prior year

Sales so far this year, the same stretch of last year, and the growth between them. The prior-year measure reuses the year-to-date one and shifts its dates back a year.

Sales YTD =
TOTALYTD ( [Sales], 'Date'[Date] )

Sales PY YTD =
CALCULATE ( [Sales YTD], SAMEPERIODLASTYEAR ( 'Date'[Date] ) )

YTD Growth % =
DIVIDE ( [Sales YTD] - [Sales PY YTD], [Sales PY YTD] )

Use DIVIDE, not /: DIVIDE returns blank when last year had no sales, where / would show infinity or an error. Time intelligence functions like these need a date table with every day, no gaps.

Running totals

A total that keeps adding up across dates. For each date in the visual, it sums sales on every date up to and including it.

Sales Running Total =
CALCULATE (
    [Sales],
    FILTER (
        ALL ( 'Date'[Date] ),
        'Date'[Date] <= MAX ( 'Date'[Date] )
    )
)

Visual by day, March 2026

How it works: ALL clears the visual's filter on the date, so the sum can reach back; MAX still sees the visual's date, which sets where to stop. March 3 had no sales, so Sales is blank there but the running total carries on at 65. This total never resets; for one that restarts each year, use TOTALYTD from the pattern above.

CALCULATE and filter context

CALCULATE changes the filters a measure runs under. The same visual shows a measure that replaces the region filter and one that removes it to get each region's share.

West Sales =
CALCULATE ( [Sales], Region[Region] = "West" )

% of All Regions =
DIVIDE ( [Sales], CALCULATE ( [Sales], ALL ( Region ) ) )

Visual by region

RegionSalesWest Sales% of All Regions

Why West Sales is 800 on every row: a filter argument like Region[Region] = "West" replaces any existing filter on that column, so the East row's filter is overwritten. To keep the row's filter and only narrow it, wrap the condition in KEEPFILTERS: then East and North show blank and only West shows 800.

Dynamic segments

Group customers into Low, Mid and High by their sales, where the bands live in a small table of their own. Because the measure checks each customer's sales at query time, the groups follow whatever filters are on the page, such as a single year.

Customers in Segment =
COUNTROWS (
    FILTER (
        VALUES ( Customer[CustomerID] ),
        VAR CustomerSales = [Sales]
        RETURN
            NOT ISEMPTY (
                FILTER (
                    Segment,
                    CustomerSales >= Segment[Min]
                        && CustomerSales < Segment[Max]
                )
            )
    )
)

Why the Segment table has no relationship: customers don't belong to a segment until their sales are known, so the link is made inside the measure. Each band's Max is excluded (<), so a customer at exactly 100 lands in Mid, not in both.
